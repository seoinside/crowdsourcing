# IMU 기반 PDR + 핑 보정 GT 궤적 생성

- 코드: `gt_reconstruct.py` (`detect_steps`, `heading_at`, `reconstruct`)
- 사용처: `build_dataset.ipynb` 셀 ④ `build_session()` → `reconstruct(gt, imu)`
- 예시 세션: `data/02_Dynamic/1DC2_20261105_212104_throttleOFF_max_gt` (S21+, 약 4.5분, 핑 12개)

---

## 0. 입력 데이터

### imu.csv
- 열: `timestamp, sensor, x, y, z, w`
- 센서별 행이 한 파일에 섞여 저장

| sensor | 주기 | 행 수 (예시 세션) | PDR 사용 | 용도 / 미사용 이유 |
|---|---|---|---|---|
| acc (가속도, m/s²) | 50 Hz | 13,676 | O | 걸음 검출, 보폭 |
| game_rv (자세 쿼터니언 x, y, z, w) | 50 Hz | 13,688 | O | 방향(yaw) |
| gyro (각속도) | 50 Hz | 13,688 | X | game_rv에 이미 반영 |
| mag (자기장) | 50 Hz | 13,680 | X | 실내 자기장 왜곡 |
| pressure (기압) | 10 Hz | 2,737 | X | 층 이동 없음 |
| step (안드로이드 걸음 감지) | 비정기 | 24 | X | 330걸음 중 24개만 기록 → 신뢰 불가 |

- 실제 사용: **acc (x, y, z)**, **game_rv (x, y, z, w)**

### gt.csv
- 열: `timestamp, seq, floor, x_m, y_m, x_px, y_px`
- 핑 = 사람이 도면에서 직접 찍은 위치 (정확한 기준점)
- 예시 세션: 핑 12개 → 구간 11개

## 1. 걸음 검출 (acc)

- 가속도 크기: `√(x² + y² + z²)`
  - 폰 방향과 무관
  - 예: 첫 행 x=−0.28, y=3.51, z=9.58 → 10.21 m/s²
- 7개 이동평균 (0.14초) → 잡음 제거
  - 정지 시 중앙값 10.04 m/s² (≈ 중력 9.8)
- 걸음 판정
  - 이동평균 값 > **10.6 m/s²** + 좌우보다 큰 봉우리
  - 봉우리 간격 < **0.3초** → 같은 걸음, 더 큰 봉우리만 유지
- 기준값 10.6 근거: 10.8에서는 느린 보행 시 걸음 누락
- 예시 세션 결과: **330걸음**

## 2. 보폭 추정 (Weinberg)

- 식: `보폭 = 0.47 × (이전 걸음 ~ 이번 걸음 사이 가속도 최대 − 최소)^(1/4)`
- 원리: 큰 보폭 → 상하 움직임 큼 → 가속도 진폭 큼
- 상수 0.47: 사람마다 다름 → 핑 보정의 배율 s로 흡수
- 예시
  - 첫 걸음 진폭 1.27 m/s² → 0.47 × 1.27^0.25 = **0.50 m**
  - 세션 전체 평균 0.58 m (범위 0.39~0.76 m)

## 3. 방향 추정 (game_rv → yaw)

- game rotation vector: 안드로이드가 자이로 + 가속도로 계산한 폰 자세 (쿼터니언)
- yaw (수평 회전각) 식: `yaw = atan2(2(w·z + x·y), 1 − 2(y² + z²))`
- 예: 첫 행 x=0.161, y=0.020, z=0.112, w=0.980
  - `atan2(0.226, 0.974)` = **13.1°**
- `unwrap`: −180° ↔ 180° 경계 값 튐 방지
- 걸음 시각 기준 보간 → 걸음별 방향
- 자기장 미사용 이유: 실내 철골·전자기기 왜곡
- 단점
  - 절대 기준(북쪽) 없음 → 시작 방향 임의
  - 시간 경과 시 자이로 드리프트 누적
  - 둘 다 핑 보정의 회전 θ로 해결

## 4. PDR 경로 누적

- 걸음별 이동 벡터: `(보폭·cos yaw, −보폭·sin yaw)`
  - y 부호 반전: 도면 이미지 좌표의 y가 아래 방향
- 누적 합 = 보정 전 PDR 경로
- 예시: 핑 1 → 핑 2 구간 (45.6초, 58걸음)

| 걸음 | 시각 | 보폭 (m) | yaw | dx | dy |
|---|---|---|---|---|---|
| 1 | 0.81 s | 0.499 | 3.2° | 0.498 | −0.027 |
| 2 | 1.79 s | 0.546 | −7.5° | 0.541 | 0.071 |
| 3 | 2.51 s | 0.576 | −5.3° | 0.574 | 0.053 |
| 4 | 3.39 s | 0.576 | 10.5° | 0.567 | −0.105 |
| 5 | 4.03 s | 0.623 | 17.8° | 0.594 | −0.190 |
| 6 | 4.57 s | 0.561 | 33.7° | 0.467 | −0.311 |

- 구간 결과: PDR 거리 6.22 m vs 핑 거리 5.47 m, 끝점 오차 6.53 m
- PDR 단독 한계: 보폭 오차·방향 드리프트·걸음 누락 누적
  - 보정 없이 세션 끝까지 적분 시 마지막 핑과 중앙값 **23 m** 차이 (24개 세션)

## 5. 핑 사이 보정 (닮음 변환)

### 원리
- 핑 = 위치 고정, PDR = 경로 모양만 사용
- 핑 A → 핑 B 구간마다 독립 보정
- 회전 θ = (A→B 방향) − (A→PDR 끝점 방향)
  - 방향 드리프트 + 임의 시작 방향 보정
- 배율 s = 핑 거리 ÷ PDR 거리
  - 보폭 오차 보정
- 보정 위치 = `A + s × rot(PDR 경로, θ)`
- 결과
  - 끝점 = 정확히 핑 B
  - 중간 = PDR 경로 모양 유지
  - 다음 구간은 핑 B에서 새로 시작 → 오차 초기화, 누적 없음

### 코드 (`reconstruct()` 핵심, 의사 코드로 축약)
```text
for i in range(len(pt) - 1):                      # 핑 i → 핑 i+1
    a, b = anchors[i], anchors[i + 1]
    m = (step_t > pt[i]) & (step_t <= pt[i + 1])  # 구간 내 걸음
    p = np.cumsum(d[m], axis=0)                   # A 기준 PDR 경로
    pdr_end, ab = p[-1], b - a
    if |pdr_end| > 0.5 and |ab| > 0.5:
        th = atan2(ab) - atan2(pdr_end)           # 회전 θ
        s = |ab| / |pdr_end|                      # 배율 s
        q = a + s * rot(p, th)                    # 닮음 변환
    else:                                         # 거의 안 움직인 구간
        frac = (걸음 시각 - pt[i]) / (pt[i+1] - pt[i])
        q = a + p + frac * (ab - pdr_end)         # 끝점 오차 시간 비율 분배
    track += q; track.append(b)                   # 구간 끝 = 핑 B
```

### 숫자 예시 (가상)
- 조건: A(0, 0) → B(4, 0) 실제 직진, PDR 보폭 0.8 m × 4걸음, 방향 −45° 틀어짐
- θ = 0° − (−45°) = **+45°**, s = 4 ÷ 3.2 = **1.25**

| 걸음 | 보정 전 p | 45° 회전 | × 1.25 = 보정 후 |
|---|---|---|---|
| 1 | (0.57, −0.57) | (0.8, 0) | (1, 0) |
| 2 | (1.13, −1.13) | (1.6, 0) | (2, 0) |
| 3 | (1.70, −1.70) | (2.4, 0) | (3, 0) |
| 4 | (2.26, −2.26) | (3.2, 0) | (4, 0) = 핑 B |

### 선형 분배 (예외)
- 조건: PDR 거리 또는 핑 거리 ≤ 0.5 m
  - 제자리 핑, 나갔다가 같은 자리 복귀
- 방향 정의 불가 → 회전·배율 미사용
- 끝점 오차를 시간 비율만큼 걸음마다 분배
  - 구간 시간 50% 지점 걸음 → 오차 50% 이동

## 6. 스캔 시각 위치

- 보정 궤적: 걸음 시각마다 위치
- Wi-Fi 스캔 위치: 앞뒤 걸음 위치 사이 시간 선형 보간
- GT 라벨: 결과 시각 직전 2초 동안 위치 5점 → 모두 한 구역 안 + 경계 0.3 m 이상 안쪽
- 첫 핑 전 / 마지막 핑 후: 기준점 없음 → 핑 위치에 정지로 간주, 걸음 검출 시 drop

---

## 7. 한계

- 구간당 θ·s 하나 → 구간 중간 보폭·방향 변화 미보정
- 핑 간격 길수록 중간 오차 증가 → 핑 사이 거리 > 5 m 구간 noisy 처리 근거
- 걸음 누락 시 배율 s 과대 (예: 5→6 구간 s = 2.95)
- 데이터 전체 핑 간격 중앙값 1.44 m (1,111개 구간) → 대부분 짧은 구간

## 전체 흐름

```
imu.csv
 ├─ acc (x, y, z)       → 크기 → 이동평균 → 봉우리 = 걸음 시각
 │                                    └→ 봉우리 사이 진폭 → Weinberg 보폭
 └─ game_rv (x, y, z, w) → yaw → 걸음 시각 보간 = 걸음 방향
                           ↓
        걸음별 (보폭·cos yaw, −보폭·sin yaw) 누적 = PDR 경로
                           ↓
gt.csv  핑 사이마다 회전 θ · 배율 s 닮음 변환 → GT 궤적
                           ↓
        Wi-Fi 스캔 시각 위치 보간 → 구역 라벨 (zone_split.label_gt)
```
